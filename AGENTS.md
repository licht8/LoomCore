# AGENTS.md — LoomCore / LoomCore

Read `RULES.md` before any change — it is the authoritative project rulebook.
All chat, comments, documentation and commit messages are **in English** (RULES 0).

## What this is

- **Core (`src/`)** — thin FastAPI layer: API, WebSocket, LLM router, plan-and-execute agent, auth, plugin manager. Entry point is `src.main:app` (`uvicorn src.main:app`), but `main.py` only calls `create_app()` from `src/app.py`; routes live in `src/api/*` (RULES 10). There is no root `main.py`.
- **Plugins (`plugins/<name>/main.py`)** — separate subprocesses talking to the core over JSON-RPC 2.0 via stdio (MCP). `plugins/LoomWG` (WireGuard) and `plugins/LoomOps` (system operations, enabled by default).
- **`frontend/`** — Next.js 16 (standalone), the hub client. Do NOT touch it without reading `frontend/AGENTS.md` (auto-generated by Next; do not delete its block).
- New functionality = a new/edited **plugin**, not core bloat (RULES 1).

## Commands

Backend (root, uses `uv` + `uv.lock`):
```bash
uv sync                              # or: pip install -e ".[dev]"
pytest                               # asyncio_mode=auto; single: pytest tests/test_rate_limit.py::test_rate_limit_429_response_body
pytest -m "not integration and not e2e"   # fast unit run (no DB/WireGuard)
ruff check .
uvicorn src.main:app --reload --port 8000
```
Frontend (`frontend/`, uses `npm` — matching the Dockerfile):
```bash
npm install
npm run dev          # port 3000
npm run build
```
Full stack / deploy:
```bash
docker compose up -d --build         # VDS: sudo bash deploy/install.sh (nginx:80; hub/frontend host-networked on loopback)
```

## Non-obvious facts

- **Migrations via Alembic only.** Startup (`src/app.py`) and `docker-compose.yml` do NOT run migrations; `deploy/install.sh` does (`alembic upgrade head`). For manual starts, run `alembic upgrade head` yourself (`alembic/env.py` uses an async engine and reads the URL from `.env`/`DATABASE_URL`).
- `src/app.py` calls `plugin_manager.discover_plugins(settings.plugins_dir)` on startup (`PLUGINS_DIR`, default `/app/plugins`) — outside Docker set `PLUGINS_DIR=./plugins`, otherwise no plugins load.
- A plugin is launched as `sys.executable <plugins/<name>/main.py>`; `plugins/LoomWG/main.py` imports the `LoomWG` package (`from LoomWG.server import run_server`), relying on the script directory being on sys.path.
- Plugin metadata lives in `plugins/<id>/manifest.json` (schema: `docs/architecture/PLUGIN_MANIFEST.md`). The core **reads and validates** it during discovery (identity/version/permissions/`default_enabled`) and warns on mismatch — a structurally invalid manifest makes `discover_plugins` skip the plugin; each plugin also self-validates against its runtime. Enable/disable state persists to `<plugins_dir>/../.loomcore/plugins.json` (`PLUGINS_STATE_FILE` override). A runnable template sits in `docs/architecture/plugin-template/` — outside `plugins/`, so `discover_plugins` does not launch it.
- The core exposes `core_*` meta-tools (`src/core/core_tools.py`) to the LLM and via `GET /api/tools`: read-only `core_health`/`core_list_plugins`/`core_plugin_status`/`core_list_tools`/`core_capabilities`, plus approval-gated `core_enable_plugin`/`core_disable_plugin`/`core_reload_plugin`. Lifecycle is also available over REST as `POST /api/plugins/{id}/enable|disable|reload` (admin, 10/min).
- **The assistant is a conversational-first agent, not a reactive tool-caller.** Default turns are plain conversation (greetings, questions, clarifying questions); a single obvious action runs as a *direct* one-step `agent_plan` with no plan card, and only multi-step / explicit / ambiguous work becomes a structured *plan*. The planner LLM is offered exactly one callable tool, `agent_plan` (the real catalog is passed as context); a deterministic executor in `src/core/agent.py` clamps the mode (`plan` when declared or more than one step, else `direct`), classifies each step's risk, and replays approved steps verbatim. Direct actions that are not safe are confirmed in plain text (`src/core/confirmations.py`, phrases in `src/core/confirmations.json`, `CONFIRMATIONS_FILE` override, 300s timeout). Plans persist in `messages.tool_calls` JSONB under `role="plan"` (no migration); the summary call is voiced by `src/llm/SOUL.md`. Safety invariant: a non-safe step runs only when the plan status is `approved`. See `docs/architecture/AGENT.md`.
- LoomOps is **deny-by-default**: `ops_run_command` runs nothing until `LOOMOPS_ALLOWED_COMMANDS` is set, and `ops_read_file`/`ops_write_file` refuse all paths until `LOOMOPS_ALLOWED_PATHS` is set (comma-separated; `:` works for paths). For read-only host observability the `hub` container grants `pid: host`, `cap_add: [SYSLOG]` and ro mounts of `/var/log`, `/var/log/journal`, `/run/log/journal` (volatile) and `/run/systemd` under `/host/...` — but **not** `privileged`, the Docker socket, `SYS_PTRACE` or `DAC_READ_SEARCH`. A journal dir is used only when it holds `*.journal` files (`LOOMOPS_JOURNAL_DIRS`); enable persistent journald or use the volatile mount otherwise. So `ops_list_processes`/`ops_scan_health` see host processes, while the four mutating tools (`ops_run_command`, `ops_write_file`, `ops_kill_process`, `ops_systemctl_restart`) stay approval-gated and audited. See `docs/plugins/LoomOps.md`.
- The plugin's WireGuard config directory is `LOOMWG_CONFIG_DIR` (default `/etc/wireguard`); tests/e2e use a temp directory.
- On firewalld hosts (RHEL/Rocky), set `LOOMWG_SKIP_FIREWALL=1`: `wg_setup_server` then skips firewall/NAT and you configure it manually.
- `deploy/install.sh` does not install WireGuard: the `hub` image ships the userspace tools, and the `wg_install_dependencies` tool (dangerous — approval) installs/repairs missing ones in-container and loads the kernel module. Only host kernel support is required (in-tree since Linux 5.6; older kernels need `kmod-wireguard`).
- Compose uses `network_mode: host` for `hub`/`frontend`/`nginx` so WireGuard + NAT live on the host; only `:80` is public, `8000`/`3000`/`5432` bind to `127.0.0.1`.
- Auth accepts **either credential** (`src/core/security.py:require_admin_token`): the static `ADMIN_TOKEN` (bearer/query), or a JWT cookie when `ADMIN_PASSWORD_HASH` + `ADMIN_TOTP_SECRET` + `SESSION_SECRET` are set. Both work at the same time, so the static token is valid even on a password+TOTP deployment (leave `ADMIN_TOKEN` empty for JWT-only). Password hash: `python -m src.auth <password>`.
- The `/ws/{session_id}` route is not wrapped by slowapi (limits are on REST: chat 30/min, auth 5/min, etc.).
- `frontend/next.config.mjs` sets `typescript.ignoreBuildErrors: true` — TS errors do not break `next build`; type-check separately (`npx tsc --noEmit`).
- Tests need no DB; integration smoke needs Postgres: `LOOMCORE_INTEGRATION=1 pytest tests/test_smoke_integration.py`. CI is `.github/workflows/ci.yml` (ruff + pytest + frontend).

## Project invariants (from RULES.md — do not violate)

- **Never delete** a file without the owner's explicit permission; if allowed, move it to `tmp/_trash/`.
- Work only inside the project; drafts/logs only in `tmp/` (gitignored).
- Do not touch other people's Docker containers; own resources use the `loom_` prefix; do not expose port 8000 publicly (nginx only).
- The coordinator commits after acceptance; the worker does not commit. Reports and task messages go in fenced code blocks (RULES 0a).
