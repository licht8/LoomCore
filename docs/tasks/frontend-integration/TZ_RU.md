# ТЗ: Интеграция фронтенда с бэкендом (WebSocket)

## Цель
Превратить статический UI (mock-данные) в рабочий интерфейс управления инфраструктурой. Подключить Next.js к FastAPI через WebSocket для получения реальных ответов от LLM, индикации набора текста (`thinking`) и управления вызовами инструментов (`tool_call` / `approve`).

## Контекст
- **Бэкенд готов:** Порт `8000`, WebSocket по `/ws/{session_id}` поддерживает весь необходимый обмен (текст, approval, status).
- **Фронтенд:** Next.js (порт `3000`), текущая вёрстка (v0) стабильна, но требовательна к аккуратности. **Ранее фиксы ломали верстку (дёрганье инпута), поэтому меняем только логику и JS, минимально касаясь CSS-структуры.**
- **Правила:** Соблюдать RULES.md (код на русском, изоляция, комментарии).

---

## Задача 1: Подключение WebSocket (State Management)

**Что сделать:**
1.  Заменить статический импорт `messages` из `lib/chat-data.ts` на реальное состояние React.
2.  Реализовать кастомный хук `useChat` (или логику в `page.tsx`), который:
    *   Генерирует `sessionId` (если нет в `localStorage` или кукисах).
    *   Открывает соединение `new WebSocket('ws://localhost:8000/ws/{sessionId}')`.
    *   Слушает события и формирует массив сообщений.

**Требования к обработке WS-событий:**
*   `thinking`: показывать "печатает..." (индикатор над полем ввода).
*   `response`: добавлять новое сообщение типа `assistant`.
*   `tool_call` / `tool_response`: добавлять сообщение типа `tool`.
*   `approval_request`: **критично!** — выводить UI с кнопками "Approve" / "Deny" (не просто текст).
*   `error`: выводить красное уведомление.

## Задача 2: Интеграция ChatInput

**Что сделать:**
1.  Обновить компонент `components/chat-input.tsx`.
2.  Связать форму с WebSocket:
    *   При нажатии Enter или кнопки "Send" — отправлять в WS JSON: `{"message": "текст"}`.
    *   Пока бэкенд думает (получаем `thinking` или `response` от LLM), кнопку отправки нужно дизейблить (`disabled={isSending}`).
3.  **Важно:** Не менять CSS-стили поля ввода и контейнера. Изменить только логику отправки (`onSubmit`).

## Задача 3: Отображение Tool Calls и Approvals

**Что сделать:**
1.  В `components/chat-message.tsx`:
    *   Для типа `tool`: отрисовать код (превью команды) и **статус**.
    *   Для статуса `pending` (ожидаем ответа): показать индикатор загрузки.
2.  В `components/chat-input.tsx` (или отдельный блок над инпутом):
    *   Если пришел `approval_request` (например, плагин хочет "reboot" или "delete"), вместо обычного инпута (или поверх него) показать диалог подтверждения: "Вы уверены, что хотите запустить `команда`? [OK] [Cancel]".
    *   Отправка: `{"action": "approve"}` или `{"action": "deny"}`.

## Задача 4: Стабилизация UI (Осторожно!)

**Контекст:** Ранее при добавлении сообщений "прыгала" панель ввода из-за изменения высоты скролла.

**Требования:**
1.  При динамическом добавлении сообщений (приходящих по WS) **инпут не должен сдвигаться**.
2.  Использовать `messages` стейт для рендера списка. Убедиться, что `overflow-y-auto` применяется корректно к контейнеру сообщений, а не ко всему экрану.
3.  **Запрещено** переписывать CSS с нуля. Использовать только существующие классы Tailwind (`flex`, `h-screen`, `gap`, `p-4`).
4.  Если нужно — добавить минимальные `padding-bottom` для контейнера чата, чтобы последнее сообщение не перекрывалось инпутом, но не ломая `flex`-верстку.

## Критерии приёмки
1.  Пользователь пишет сообщение -> Bэкенд отвечает через пару секунд.
2.  Появляется индикатор "печатает...", затем ответ.
3.  Если бэкенд вернул `approval_request` -> Пользователь видит кнопки.
4.  Верстка стабильна: при быстром наборе чата инпут не "прыгает".
5.  Консоль браузера чиста (нет 404 и крэшей).
